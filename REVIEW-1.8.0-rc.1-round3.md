## 🔴 Blockers (both adversarially verified)

### B1 — `setByPath` crashes on an intermediate segment whose own value is `undefined`
`src/by-path.ts:139-150`

`byKey` changed from `obj[key] === undefined` to a `hasOwnProperty` test for **both** the insert decision and the return value. A key that exists as an own property holding `undefined` short-circuits both halves: nothing is inserted, `undefined` is returned, and the inner `while` loop in `setByPath` (no null guard — only the outer loop has one) dereferences it at `src/by-path.ts:287`.

Reproduced independently during triage:

```
setByPath({app:{config:undefined}}, 'app.config.theme', 'dark')
→ TypeError: undefined is not an object (evaluating 'obj[key]')
→ object left mutated to {"app":{}}
```

On `v1.7.9` the same call produced `{app:{config:{theme:'dark'}}}`. Confirmed regression, raw TypeError from library internals, no in-app workaround short of pre-creating every container.

**Two triggers, not one.** The finding names TS placeholder state (`user: undefined as User | undefined`, which the docs' own bind-before-data guidance encourages). The verifier found a second and more common one: **clearing a subtree.** `xin['app.config'] = undefined` writes an own property holding `undefined`; the very next deep write crashes.

**Escapes the library.** `applyInbound` in `src/share.ts:275` and `src/sync.ts:219` call `setByPath(registry, path, value)` with no try/catch, so an ordinary peer/server delta arriving under an `undefined` placeholder throws inside the BroadcastChannel / transport receive handler (see M1 — the two compound).

The change's intent is sound and still works (`setByPath({app:{}}, 'app.toString.x', 1)` correctly creates an own container rather than descending into an inherited member). The guard is over-broad, not wrong.

**Fix:** treat own-but-`undefined` as absent for the insert decision, keep `hasOwnProperty` for the inherited-member case:
```
if ((!own || obj[key] === undefined) && valueToInsert !== undefined) obj[key] = valueToInsert
```
returning `undefined` only for the inherited-and-not-inserted case. **Add regression tests in `src/by-path.test.ts`** (which this diff never touched) for: `setByPath({a:{b:undefined}}, 'a.b.c', 1)`; the same via `xin['a.b.c'] = 1`; and the clear-then-rewrite sequence `xin['app.config'] = undefined` → `xin['app.config.theme'] = 'dark'`.

### B2 — The manifesto's flagship live demo calls `agent.call()` on a read-only surface
`one-user-interface.md:70` (and shipped at `docs/one-user-interface/index.html:111`)

The page does `const agent = enableAgentInterface()` with no `expose`. Since the safe-by-default change (`2b790da`) plus the security pass (`259d611`), that is the **read-only** posture — `callsAllowed = exposeAll || manifestMode` is false, so `assertMutable` (`src/agent.ts:968-981`) throws. Verified by running the snippet:

```
agent.read('oneUI.list')            → works
agent.call('oneUI.addItem', 'x')    → Error: agent interface: call("oneUI.addItem")
                                       refused — this surface is read-only introspection.
```

`git show 2b790da --stat` confirms that commit updated `agent-surface.md` and `derived-surface.md` (and their rendered pages) but **never touched `one-user-interface.md`**. Every sibling page uses the corrected `globalThis.tosiAgent ?? enableAgentInterface({ expose: 'all' })`; this one was left behind.

The page contradicts itself: line 16 states the no-arg call is read-only by default; 54 lines later the demo depends on the pre-change behaviour. The "Agent (paths only)" button and the prose at :159-161 (`tosiAgent.call('oneUI.addItem', 'from the console')`) both fail. This is the parent page of the release's namesake feature, self-described as "the thesis and its live proof", and it is a ```` ```js ```` fence — neither `bun test` nor the Playwright doc-test lane covers it.

**Fix:** prefer `enableAgentInterface({ expose: { roots: ['oneUI'], actions: ['oneUI.addItem'] } })` — it demonstrates the production posture the page's own banner advertises *and* makes the demo work. Then re-run the page and click both agent buttons. Add a ```` ```test ```` fence exercising `call`/`read` so the browser lane guards it.
