## BLOCKER (1)

### B1 — A `static contract.value` violation aborts the whole binding-dispatch loop, silently stranding every later-bound element

`src/component.ts:1143` (throw) → `src/bindings.ts:151` → `src/dom.ts:155` → `src/bind.ts:372` (unguarded loop)

`checkValueContract` throws a `TypeError` from the `value` setter **before** assigning. `bindings.value.toDOM` _is_ `setValue`, which does `element.value = newValue`, so the throw lands inside the global observer's `for (const element of boundElements) touchElement(...)` loop — which has no `try/catch`. `path-listener` catches at the listener level, so **the rest of the loop never runs**.

Reproduced three ways:

- A contracted component bound before a sibling on the same path: setting a bad value logs `Listener … threw "TypeError: <ctr-counter> value contract violation…" handling "q.n"` and the sibling stays stale while state says otherwise.
- **It fires with no user error present**: under the documented deeply-async pattern, `setValue` writes `''` while state is still `undefined`, so `{ value: { type: 'number' } }` throws at bind time — and a sibling bound afterwards receives _zero_ initial `toDOM` calls.
- The same throw kills a component's own change handler mid-commit before `this.value` is assigned — **the exact 1.7.7 regression that got a release deprecated on npm.**

`src/contract.test.ts:386-460` only covers direct writes (`el.value = 'seven'` inside `expect().toThrow()`); nothing drives a violating value through a binding.

**Fix before tagging (both halves):**

1. Do not throw from the `value` setter on the `toDOM` path — report (`console.error` + a `contractviolation` event / `internals.setValidity`) and still assign, or keep the throw only for direct programmatic writes.
2. Independently, wrap `touchElement` in a `try/catch` inside the `for (const element of boundElements)` loop at `src/bind.ts:372` (and the identical MutationObserver loop at `:348`) so one element's failure can never strand the others.
3. Regression test: contracted component + a second bound element on the same path, bad write, assert the second element still updated. Plus a bind-before-data case.

## Release gates not satisfied (must resolve before final tag)

- **No security lens ran.** The headline feature is a new remotely-drivable control surface. `enableAgentInterface()` defaults (`src/agent.ts:618`) are `global = true, webmcp = true`, and no `expose` ⇒ `manifestMode = false` ⇒ every registry root is **read, write and call** exposed on `globalThis.tosiAgent` and auto-published to `document.modelContext` (including `tosi_write`, registered by default at `src/webmcp.ts:144`). The project's own `trust-and-transports.md` says the honest production posture is "manifest-only, allowlist, never denylist" and "open `write()` is a dev-mode affordance" — **the shipped default is the exact opposite**, and any third-party script or XSS on the page inherits it. Nobody reviewed default-safety, origin gating, or the secrets/PII exposure path. See M5.
- **No CI lane has ever run against this release.** `.github/workflows/ci.yml` triggers only on `main`; `one-user-interface` has 99 commits not on `origin/main` and is deliberately never pushed. Neither the `unit` lane nor the `e2e` Playwright lane has executed against ~15,000 inserted lines, six new modules, two new package entry points, or a new published `bin`. See M19.
- **The mandatory browser lane has no new coverage.** `tests/` is unchanged in the entire diff, yet `component.ts` (+249), `elements.ts` (+57) and `bind.ts` changed DOM behavior. CLAUDE.md makes `bun run test:browser` a non-optional gate for exactly that; 1.7.7's segmented regression is the precedent. At minimum run it locally and record engines + result in the RC notes.

## MAJOR findings (24 verified)

### Correctness / security

**M2 — `on<Event>` member-wins is value-dependent, and the shipped warning states the opposite of what the code does.** `src/elements.ts:578`
The gate is `typeof existing === 'function'`. A prototype method or arrow-field member wins (as advertised); a **null/undefined-initialised class field still gets event sugar** — the original footgun, unchanged — while emitting the warning "_your member WINS: creator({ onProgress: fn }) assigns it rather than attaching a 'progress' listener_". That sentence is false for the field case. Separately, when the member _does_ win, a caller's `onClose: fn` silently overwrites the component's own prototype method **and** stops being a listener — both sides break at once, with no call-site diagnostic. The only regression test (`src/component.test.ts:1842`) uses a prototype method. `CHANGELOG.md:99-101` and `src/component.ts:403` each state a third, different rule. Decide the winner from the _declaration_ (an opt-in `static memberProps`, or only when an own descriptor exists), never let a caller's prop overwrite a prototype method, and make warning + CHANGELOG + doc block say the same thing.

**M1 — The new `typeMismatch` branch in `elementProp` breaks third-party web components (regression vs 1.7.9).** `src/elements.ts:475`
`declared` reads the element's _current property value_, not a declared type, and `typeof null === 'object'`. A third-party element with `count = null` + `observedAttributes` + ACC-driven render now takes `elt[key] = value`: the attribute is never written, `attributeChangedCallback` never fires, the widget renders nothing. Verified against v1.7.9 source: `getAttribute('count')` was `"5"`, is now `null`. Wider than filed — `elementPropBinding.toDOM` calls this on _every_ reactive update, so the common `this.foo = newValue` idiom makes later numeric/boolean updates swallow silently, and boolean attributes stop toggling (the attribute is never removed). The existing third-party regression tests pass only because every fixture declares properties without initialisers. Base the test on a declared type (tosijs `Component` `initAttributes`) or require `declared != null`.

**M3 — A subclass declaring `contract.attributes` silently discards every inherited `initAttributes`.** `src/component.ts:841`
`_resolveInitAttributes()` uses `hasOwnProperty` on both, so the same-class "declares BOTH" throw is skipped and the contract branch returns _only_ the contract map. Verified: `Child.observedAttributes` loses `size`; `child({ size: 42 })` sets the attribute while `child.size === undefined` — reflection severed in both directions, no throw, no warning. Mirror case identical. This is exactly the intended migration shape (add a contract to a subclass of an `initAttributes` base). Walk the prototype chain and merge (subclass wins per key); keep the same-class throw.

**M4 — `contract.description` is stamped as `aria-label` on every connect, overriding the real accessible name.** `src/component.ts:1631`
Gated only on the absence of `aria-label`/`aria-labelledby`/`title` — no check for visible content or role. A `role="button"` component whose content is `Save` announces the developer-facing prose instead (the CLI template's default description literally contains an instruction to the developer). No runtime opt-out: `removeAttribute` + detach/re-append re-stamps. Shadow-DOM components (implicit `role=generic`, naming prohibited) get it too — an axe `aria-prohibited-attr` violation. And `describeElement` reads `aria-label` first, so `auditAccessibility`'s `anonymous-affordance` rule is silenced by tosijs's own stamp: **the audit grades the library's homework.** Map it to `aria-description`/`aria-describedby`, or gate on empty content + a name-from-author role with an explicit opt-out.

**M5 — The scaffolder writes a default-open, write-capable agent surface into every generated app.** `bin/cli.ts:308`
`bunx tosijs create app` emits a bare `enableAgentInterface()`. The generated project has one script (`bun index.html`) and no dev/prod distinction. Result: `globalThis.tosiAgent` with read/write/call over the entire registry, plus auto-registered `tosi_write` whose own description says "DEV MODE: writes are unvalidated". `grep console.warn src/agent.ts` returns nothing — zero runtime signal. Mitigating (verified): the template does carry a three-line comment naming the production form, the module is flagged EXPERIMENTAL, and the scaffold has no production build path — which is why this was adjusted from blocker to major. **Still fix in this pass** (cheap): (1) one `console.warn` when entering introspection mode, naming `expose` and the fact that `tosi_write` is live; (2) require explicit `allowWrites: true` for `tosi_write` instead of treating introspection mode as consent; (3) scaffold the curated form with a commented "widen for dev" line; (4) document it in the scaffolded README.

**M6 — Public API removed on a MINOR bump; the markup removals fail silently.** `package.json:3`
1.8.0 removes `xinSlot`, `blueprint`, `blueprintLoader`, `<xin-slot>`, `<xin-blueprint>`, `<xin-loader>` and `data-ref`. `CHANGELOG.md:5` claims SemVer adherence. `semver.satisfies('1.8.0', '^1.7.8')` is true and tosijs-ui declares `"tosijs": "^1.7.8"`, so consumers get it on next install without touching their code. The JS removals break loudly; **the markup path does not** — `BlueprintLoader.load()` now queries only `'tosi-blueprint'`, so a legacy page gets an unregistered element, no hydration, no console output, no exception (reproduced: `warns: []`, `errors: []`). The one orphan-blueprint dev warning queries only the `tosi-*` tags and lives in `index-core.ts`, not the full entry. Either cut this as 2.0.0, or keep the three custom elements one more cycle as thin loud-erroring registrations. The `1.8.0-rc.1` prerelease does not yet propagate — this lands the moment final `1.8.0` moves `latest`.

**M7 — No 1.8.0 section in `Migration.md`, and three doc surfaces still promise the removed names "continue to work".** `Migration.md:3`
`Migration.md` is byte-identical to v1.7.9; its newest section is "Upgrading to 1.7.0", which states verbatim "No API was removed or renamed." Its page description — surfaced in nav, search, `docs/docs.json` and `llms.txt:57` — says "Old names continue to work with one-time deprecation warnings." `README.md:464` and `src/docs/history.md:73` repeat it. Two behavior changes (M1, M2) had **no** prior deprecation warning at all. Add "Upgrading to 1.8.0" with a before→after table (`data-ref="x"` → `part="x"`, `<xin-blueprint>` → `<tosi-blueprint>`, `blueprintLoader()` → `tosiLoader()`, `xinSlot()` → `tosiSlot()`), the two behavior changes, and the Apache-2.0 relicense; scope the three "old names still work" sentences to the surviving aliases.

### Efficiency

**M8 — The agent audit ledger grows without bound.** `src/agent.ts:661-668`
`observe(() => true, path => ledger.push({ seq, path }))`, no cap, no ring buffer, no trim; `changes()` reads backwards without consuming, `log()` is a full `slice()`. In the **default** (non-manifest) mode `inScope` is unconditionally true, so every path in the whole registry is recorded — manifest mode is the narrower case. Measured: 20,000 settled touches → 20,000 entries, 3.20 MB heap. Coalesces per settle round, so the real rate is ~one entry per frame/message, forever; the documented pattern is enable-once-and-leave. Add `maxLog` with a ring buffer (keep `seq` monotonic; signal truncation when a drain spans dropped entries), or key state touches by path in a `Map`.

**M9 — `describe()` measures and style-probes elements it immediately discards.** `src/agent.ts:838`
`measureBounds()` (a `getBoundingClientRect` plus an unconditional fixed/sticky walk calling `getComputedStyle` on up to 12 ancestors) runs _before_ the `if (!wired)` bail at `:856` that throws the record away — and every custom element on the page is fed in. Instrumented: 200×4 fixture → 200 records, 1,400 rects (71.4% discarded), 5,200 style resolutions (26 per surviving record); unwired custom-element ancestors are then measured a _second_ time by the structural tier. The documented pattern redraws from `agent.observe(/./, requestRedraw)` at 100 ms debounce. Fixes: reorder (pure move below the bail), memoize the ancestor probe in a per-pass `Map`, and add `describe({ bounds: false })` for the `exerciseContract()` / `webmcpTools()` callers that walk the document just to read `.contract` / `.actions`.

**M10 — The default bundle grew 46%, and `tosijs/core` is 39% larger than v1.7.9's entire library.** `src/index-core-exports.ts`
Measured gzip: `module.js` 24,351 → 35,702 B; `index.js` (the IIFE / CDN / `browser` condition, no tree-shaking) 24,625 → 35,993 B; `core.js` 33,979 B. Isolated cost over a typical app surface: agent +4,831 (it pulls webmcp), schematic +2,962, audit +1,259, contract +1,057 ≈ 11.2 kB gz. All exported from `index-core-exports.ts`, i.e. from **both** `tosijs` and `tosijs/core`, so the slim door saves only 1.7 kB and sheds none of the new weight. Bundler consumers are unaffected (verified: esbuild shakes it all out). 1.8.0 is the moment to draw the line: move the agent/schematic/audit/contract/webmcp surface behind a `tosijs/agent` subpath, drop it from `index-core-exports`, ship it as a separate IIFE, and add per-entry gzip budgets to `src/entries.test.ts`. CHANGELOG's "~3.7 KB" and "~32 KB vs ~34 KB" both understate.

### DRYness

**M13 — `underRoot()` re-implements `extendsPath()`, and it guards the manifest exposure boundary.** `src/agent.ts:377`
Character-for-character the same segment-boundary rule as `path-listener.ts:120` — which `agent.ts` already imports from, and which commit `d4db2ca` ("segment-boundary path matching — one helper, four sites") deliberately consolidated one release ago after raw `startsWith` matched name-prefix siblings. Exhaustive cross-product over 15 adversarial paths: 0 differences today. It is the gate for `inScope()`, `writable()` and contract-root routing — i.e. what a production manifest may read and write. Delete it; call `extendsPath(root, path)` at the four sites (argument order is swapped).

**M14 — WCAG 2.5.8 target-size and the "is this interactive" predicate are implemented twice and already disagree.** `src/audit.ts:190` vs `src/schematic.ts:469`
`audit.isInteractive` includes `href`; `schematic.interactive` does not. `audit`'s inline-link exemption uses `label ?? text`; `schematic.textSizedLink` ignores `label`. Reproduced both directions: an icon-only `<a href onClick aria-label="Buy">` at 20×20 → audit CLEAN, schematic draws an amber `target-size` bar with a legend; a nameless 16×16 `<a href>` → audit reports `target-size`, schematic draws nothing. Same library, same element, two answers, inside the workflow `audit.ts`'s own doc block recommends. `producerTargetFlag` does not reconcile them. `src/schematic.ts` is machine-vendored (`DO NOT EDIT`, regenerated by `vendorSchematic()`), so **this must be fixed upstream in tosijs-floorplan and re-vendored** — see UPSTREAM section.

### Coverage

**M15 — The `tosijs/core` blueprint-orphan warning is not merely untested; it is inert.** `src/index-core.ts:36` + `src/entries.test.ts:120`
The test captures `console.warn` into a `warnings` array and never asserts on it; its only assertion is an `||` whose right side is always true (an earlier test in the same process registered `tosi-blueprint`) _and_ whose left side is also always true (happy-dom's `:not(:defined)` does not discriminate — a deliberately garbage selector passes the same assertion). **M16 — The #18 DOM-free acceptance test reads a bundle that does not exist yet, so it is skipped on every release build.** `src/entries.test.ts:42`
`buildLibrary()` runs `bun test src/` at `bin/site.ts:99`; `dist/state.js` is written at `:130`. Worse than filed: `buildSite()` runs first and `rm -rf dist`, so at test time `existsSync('dist/state.js')` is **false** and line 48 silently returns — it tests nothing, not even the previous release. The post-build smoke gate cannot close it: `bin/site.ts:204-215` injects happy-dom's `window`/`document` onto `globalThis` before importing (verified: a module whose first statement is `document.createElement` passes the probe and fails under bare `node`). **M17 — The agent surface has zero list-binding coverage, and `cloneWithBindings` contract propagation has no test at all.** `src/agent.test.ts`

## Completeness gaps (areas no lens covered)

1. **Security lens absent entirely** — see Release gates. The single most important omission.
2. **`share.ts` / `sync.ts` untouched but affected, unreviewed.** Contract enforcement lives only in `agent.write`. Cross-tab BroadcastChannel writes and network `SyncTransport` writes land in the registry with **no** contract check, so a peer tab or sync server can install exactly the illegal state an agent is refused. Same for `hot-reload.ts` (agent-written state persisted to localStorage). The claim that "state-level validation is a hard prerequisite" has a hole.
3. **`list-binding.ts` (virtual scrolling) untouched but affected, unreviewed against `describe()`.** A virtualized list only has rendered rows in the DOM, so the affordance map and schematic silently under-report the visible window as the whole list — with no way for an agent to tell. No ListBinding case exists in `agent.test.ts` or `schematic.test.ts` (see M17).
4. **The Chrome Canary WebMCP claim is unreproducible.** "verified registering _and executing_ in Chrome Canary 153" is the load-bearing evidence for the integration and rests on one manual session; `src/webmcp.test.ts` only exercises a mock host.
5. **No size regression guard anywhere.** No gzip assertion in the suite or build; the "~3.7 KB agent surface" and "~32 KB core" CHANGELOG figures both understate and nothing would catch the next 11 kB (see M10, M11).
6. **The scaffolder is tested as strings, not as a CLI.** `src/cli.test.ts` asserts against template source text; nothing runs `bin/cli.ts` end-to-end (argv parsing, `--bare` routing, mkdir, the `existsSync` overwrite guard), and "app: runnable tree" / "blueprint: publishable package" are never proven by `bun install && bun run build` inside a scaffolded directory. This is most users' first contact with 1.8.0.
7. **The vendoring seam is a build-reproducibility hole.** `tosijs-floorplan` is a `^0.3.0` devDependency whose _source_ compiles into every published bundle; two builds of the same commit can ship different vendored code, and that code is not covered by tosijs's tests.
8. **The relicense has no dependency-compatibility or downstream audit.** Relicense authority is clean (single author across all commits since v1.7.9), but nobody checked whether tosijs-ui / react-tosijs / ngx-tosijs / tosijs-3d restate tosijs's license as BSD-3 in their own LICENSE/NOTICE/README, nor whether any consumer is GPLv2-only. The CHANGELOG raises the GPLv2 incompatibility and then drops it.
9. **`auditAccessibility()`'s WCAG claims are self-asserted.** `contrastRatio` is never validated against published WCAG reference pairs, and no finding is cross-checked against an external checker (axe et al.). A tool that tells authors their UI is accessible carries legal weight and was reviewed as ordinary code.
10. **`describe()`'s cost is undocumented and unbenchmarked**, and WebMCP hosts may call it every turn (see M9).
11. **The `on()` proxy-handler normalization (`src/bind.ts:719`)** rewrites the caller's `eventHandler` to a string path before storing; nothing verified that the returned `RemoveListener`, handler dedup and `cloneWithBindings` still behave identically when the same proxy is passed twice, or that a caller holding the original function reference can still remove the listener.
12. **Downstream ecosystem never built against the RC.** tosijs-ui `^1.7.8`, tosijs-3d `^1.7.8`, ngx-tosijs `^1.6.10` — all caret ranges that auto-resolve to 1.8.0. None was installed or built against `1.8.0-rc.1`. `tosijs-ui/CLAUDE.md:243` still instructs authors to use `xinSlot()`.
