## Blockers — fix before tag

### B-1 · `data-tosi-secret` on an `<option>` silently stops working: the `<select>`'s live value is published in cleartext
`src/agent.ts:2585-2596` · correctness · **verified by execution, both sides of the commit**

Fixture: `select({onChange}, option({value:'plain'}), option({value:'SENSITIVE-9999','data-tosi-secret':''}))`, `select.value = 'SENSITIVE-9999'`, `expose: 'all'`.

```
base (254242d~1): {"tag":"select","on":{...},"secret":true,"bounds":{...}}    <- value withheld
HEAD  (254242d):  {"tag":"select","on":{...},"value":"SENSITIVE-9999",...}    <- value published
```

Mechanism. `suppressHarvest` (`src/agent.ts:1673`) now sets `record.secret = true` only on the `'own'` branch; containment returns `'contains'` and leaves the flag unset — deliberately, and correctly, per this commit's own M-1 invariant. But the unbound-form-control harvest still gates on `record.secret !== true`, i.e. on the **flag**, while both sibling harvests in the same block — `record.text` at :2570 and the contenteditable `record.value` at :2655 — gate on `mayNotCarryContent`, the actual "may this record carry content" answer. Containment therefore opens the gate. This is the single site that reads the flag as a proxy for the decision, which is exactly the per-site restatement the function's own comment at :1651-1690 warns about: *"a live-state field added later inherits the guard by construction"* is only true for sites that go through the choke point, and this one does not.

Reachability is narrow and worth stating alongside the block: `expose: 'all'` (dev posture) plus a `<select>` with a descendant matching `SECRET_CONTROL_SELECTOR`. `<input>`/`<textarea>` admit neither element children nor shadow roots, so `<select>` + marked `<option>`/`<optgroup>` is the only shape. Marking the `<select>` itself, or wrapping it in `[data-tosi-secret]`, routes through `'own'` and stays protected — which is why the only existing `<select>` secrecy fixture (`src/agent.test.ts:2136`, `autocomplete="cc-number"`) does not see it. It requires the dev posture, but secrecy is the *only* protection that survives `expose: 'all'`, which is why the suite's own harvest-redaction tests run there.

**Fix.** Add `!mayNotCarryContent &&` to the guard (the variable is in scope, assigned at :2567). Keep `record.secret !== true` too — they answer different questions and both are wanted. A candidate fix validated in scratch: gating on `!mayNotCarryContent && !contentWithheld(el)` removes `value`, does **not** set `secret: true` (so the round-10 M-1 invariant still holds), and `bun test src/agent.test.ts src/audit.test.ts` stays 147/0.

**Pin it.** A `<select>` carrying a `data-tosi-secret` `<option>` under `expose: 'all'` must not publish `value`. While there, grep every post-`suppressHarvest` reader of `record.secret` (:2589 is currently the only one) and decide per site whether it wants the flag or the decision.

**Re-review scope:** correctness + blast-radius over the remediation diff only — re-run the agent-surface secrecy suite and re-check that no consumer of `record.secret` downstream of :2567 relied on the flag meaning "suppressed".

## Majors — fix now or file with an owner

### M-1 · `auditAccessibility()` fabricates `anonymous-affordance` and `target-size` errors on ordinary, correctly-named links inside `data-tosi-secret` regions
`src/agent.ts:1876` + `src/audit.ts` · correctness · **verified by execution**

Two geometrically identical, identically-named links, one inside the region:

```
region: a({href:'/account/reset?t=TOK'}, 'Forgot password?')  120x18 -> anonymous-affordance (error) + target-size
plain:  a({href:'/help'},                'Forgot password?')  120x18 -> neither
base:   the secret anchor was absent from `wiring` entirely -> nothing reported
```

Both findings are false. The link has visible text; at 120x18 it is exactly the inline shape WCAG 2.5.8 exempts. They fire because their **inputs were redacted**: `accessibleName()` sees `''` because `record.text` was withheld, and `targetSizeFinding`'s inline exception (`w.tag==='a' && w.text!=='' && width>height`, `schematic.ts:396`) cannot fire for the same reason. The new `if (href && secretHere) record.interactive = true` restores interactivity but nothing restores nameability, and `src/audit.ts` contains no occurrence of `secret` at all — it cannot know its inputs were redacted. The message then tells the author to "Add aria-label, a `<label>`, or visible text" on an element that already has visible text.

Two refinements from verification, both worse than reported: (a) `aria-label` rescues only `anonymous-affordance` — a labelled inline link inside the region **still** reports `target-size`, because the exemption keys on `w.text`, not `w.label`; (b) the sibling class already existed pre-commit for *wired* elements (`button({onClick},'Sign in')` in the region reports `anonymous-affordance` at both base and HEAD), so this commit widens a 1.11.0-era class. 1.11.0 is unreleased, so it is in scope either way. `anonymous-affordance` is severity `error`, so this also inflates `report.failed` — the value a CI gate asserts on.

Round 10 anticipated the class (`reviews/1.11.0-preminor-round10.md:80`: "dropping it would trade a leak for a false anonymous-affordance") but the implemented fix restores the record without restoring nameability, trading silence for a false positive rather than a true one. The commit's new test deliberately uses a *nameless* 16x16 anchor — the one shape where both findings are true — so it asserts the intent while being blind to the case it creates.

**Two viable shapes.** (a) Carry content-free PRESENCE signals beside `secret: true` — `named: true`, and a boolean standing in for "has visible text". A boolean is not content, so the new "redaction must not co-occur with what it withheld" invariant still holds. (b) Have `auditAccessibility` ABSTAIN on `w.secret === true` for `anonymous-affordance` and for the inline-exception arm of `target-size`. Abstaining is honest; fabricating is not. Either way add the mirror pin next to the new test: a NAMED, normally-sized text link inside a secret region must produce the same findings as the identical link outside it (today: two vs zero). Correct the CHANGELOG sentence, which says the audit "still reports anonymous-affordance and target-size on it" without noting it now also reports them where it should not.

### M-2 · The B-4 remediation republishes an arithmetic that does not add up, and the docs page renders it mangled
`src/index-agent.ts:40-45`, `CHANGELOG.md:310` · blast-radius + correctness (merged) · **verified by re-running the build's own measurement**

`src/index.ts` → 44_703 gz, `src/index-browser.ts` → 28_995 gz, delta 15_708 = ~15.3 **KiB** — what `<!--agentmarginal-->` emits and what the headline says. The two hand-typed supporting figures in the same sentence, "(44.7 kB)" and "(29.0 kB)", are those byte counts divided by **1000**. In KiB they are 43.7 and 28.3. A reader who does the subtraction the sentence invites gets 15.7. Every generated figure in the build divides by 1024 (`bin/site.ts` `kb()` :713, `agentDelta` :749, `agentMarginal` :782, budget log :488), so these two are the only /1000 figures published anywhere.

Propagation widened this release: `/src` is now in `files`, so this block ships in every consumer's `node_modules` as well as on tosijs.net, in `docs/index-agent/index.html` and in the ePub. This is the exact block rewritten this round *because* it published a wrong size figure, and the generator was introduced this round precisely to stop hand-maintained sizes.

Second instance, same class, same diff: `CHANGELOG.md:310` says the tjs budget raise "is right-sized by their +1_711" while the table eleven lines above says +1771 and +1767 — a transposition three lines above a block-quote warning that any hand-pasted figure there is unverified. All seven rows of that table reproduce exactly against the committed `dist/`; only :310 is wrong.

Third, found during verification and unreported: `docs/index-agent/index.html:120` renders `**</del>15.3 kB is the marginal cost of this import**` — the two bare `~` prefixes in the new block-quote are parsed as markdown strikethrough delimiters, mangling the sentence on the published page.

**Fix.** `(44.7 kB)` → `(43.7 kB)`, `(29.0 kB)` → `(28.3 kB)`, `+1_711` → `+1_771`, escape or reword the `~` prefixes, then rebuild so `docs/`, the ePub and the source fingerprint follow. Re-review scope: Tier 0 only.
