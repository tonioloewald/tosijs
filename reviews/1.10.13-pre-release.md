## Blocker

### B1. A mid-path `__proto__` still hands out the raw prototype (security and correctness; confirmed by two skeptics; reproduced in triage)

- **What happens.** With `tosi({ pp: { map: {}, rows: [{ id: 1 }] } })`, each of these returns the raw `Object.prototype` with no `UnsafePathError`:
  - `boxed['pp.map[=__proto__].value']`
  - `boxed['pp.map.__proto__.value']`
  - `boxed.pp.map['[=__proto__].value']`
  - `xin['pp.map.__proto__.xinValue']`

  `boxed['pp.rows[=__proto__].value']` returns `Array.prototype`. Assigning a property on the result pollutes every object. The terminal spellings (`boxed['pp.map[=__proto__]'].value`, `boxed.pp.map.__proto__`) throw as intended: moving `.value` inside the path string opens the door.
- **Cause.** The get trap checks the raw key (`src/xin.ts:1304`) and the normalised last segment (1421, 1427). The compound branch resolves its base with `getByPath(target, basePath)` at `src/xin.ts:1410`, which is unguarded for reads, and re-enters the trap only for the sub-path. The comment at 1302-1303 ("every spelling reaches it") is false.
- **A second exit, found by the completeness pass and reproduced in triage against `src/`.** Under `expose: 'all'`, `agent.call('app.list[=__proto__].push', 'x')` returns 1 and leaves `[][0] === 'x'` page-wide.
  - Manifest mode refuses it (exact action match).
  - The WebMCP action tools are generated per declared action, so a model host cannot supply this path through them.
  - The 1.10.12 parity for this exit is the completeness pass's claim, not re-run here.
- **Not a regression.** The committed bundles at v1.10.10 to v1.10.12 behave identically (skeptics). Published 1.6.4 and 1.8.0 do too (security lens only). Writes through the same paths are still refused at the sink, and `agent.read()` returns `undefined`.
- **Impact, rated separately from the block: low to moderate.** It needs app code that indexes a proxy with an untrusted path and then mutates what it read, or a caller-chosen path into `agent.call` under `expose: 'all'`.
- **Why it blocks.** The release would publish a Security note that a one-token variant falsifies:
  - `CHANGELOG.md:35-52` says the proxy "now refuses the key of a `[=key]` segment like any other key" and lists only inherited `constructor` under "Not closed here".
  - `SECURITY.md:62-64` puts the proxy in scope "whatever its spelling".
  - The test title at `src/xin.test.ts:2197` and card #4271's table ("refused in 1.10.13") say the same.
  - The disclosed residual yields the `Object` constructor from one path string; this yields `Object.prototype` directly.
- **Cycle basis.** The guard is the remediation of 1.10.11's B2 (`58f49499`), patched again in `ddf29eff`. `reviews/1.10.11-preminor.md` asked for the guard "on every base and sub path the compound branch splits off"; the base was not covered. This is the third release to add hand-listed rows to the #56 test.

  - Guard the base segment as normalised. The lens trialled `assertSafeLeafKey` on the normalised `basePath` ahead of line 1410 in a scratch clone: 13 probes throw, the suite stays at 1159 pass, and that site accounts for all 103 doors in the corpus.

## Fix before the tag

### M1. The documented `setContractValidator(validate)` installs a sampled validator (correctness and blast-radius; confirmed by two skeptics; re-measured in triage)

- **Measured** with tosijs-schema 1.6.0 and schema `{ type: 'array', items: { type: 'number', minimum: 0 } }`, placing one bad item at each position in turn:

  | Array length | Bad positions accepted, direct wiring | Strict wrapper |
  | --- | --- | --- |
  | 50 | 0 of 50 | 0 |
  | 193 | 0 of 193 | 0 |
  | 194 | 97 of 194 | 0 |
  | 300 | 200 of 300 | 0 |
  | 1000 | 900 of 1000 | 0 |

  `maxProperties: 1` on a three-key object returns `null` with the direct wiring and "schema violation" with the strict wrapper.
- **Reach.** Sampling starts at 194 entries (the finding's "over 97" is the upstream README's wording). The stride is deterministic, so a writer can pick unsampled positions every time. The skeptics drove it end to end through a component `value` contract and through `agent.write()` with an inline contract: a 300-item write with `-1` at index 100 lands.
- **Not a regression.** The 1.10.12 example sampled the same way. What is wrong is that the Security and Migration text says the direct form "now enforces".
- **Fix.** Teach the strict form, `setContractValidator((value, schema) => validate(value, schema, { strict: true }))`, with one sentence on why, in all five places:
  - `src/contract-check.ts:19`
  - the `onError` example at 26-32
  - the `{ final: true }` line at 50
  - the runtime warning near line 209
  - `CHANGELOG.md:22` and `Migration.md:23-25`
- **Clears when** a test in `src/contract-check.test.ts`, through the documented call, refuses all three of the cases below, and goes red when the wrapper is swapped back to bare `validate`. No re-review needed.
  - a 1000-item array with a bad item at index 2
  - a 1000-key `additionalProperties` map with one bad key
  - `maxProperties: 1` on three keys
- **Size.** The warning is a shipped string, so check the ledger.

## Deferred majors

### D1. Agent-surface gates compare the caller's spelling (security; confirmed by a skeptic; three doors reproduced in triage against `src/`)

- **Measured** with manifest `{ roots: ['app'], actions: ['app.checkout'], write: true }`:

  | Canonical spelling | Result | Respelling | Result |
  | --- | --- | --- | --- |
  | `write('app.checkout', 'x')` | refused (SEC-9) | `write('app[=checkout]', 'x')` | accepted; the action is now a string |
  | `write('app.gate.level', 'seven')` against an inline `{ type: 'integer' }` | refused | `write('app.gate[=level]', 'seven')` | accepted |
  | `read('app.login.password')` | `⟨secret⟩` | `read('app[=login].password')` | `"hunter2"` |

- **Skeptic only.** A respelled write does not update bound controls or fire the canonical observer. List-secret respellings (`rows[ 0].pw`, `rows[0x0].pw`, `rows[label=one]`) return cleartext.
- **Cause.** `writable()` and `hitsDeclaredAction` are string-prefix tests (`src/agent.ts:2572-2576`). `inlineSchemaFor` matches `b.path === path` (2272-2288). `toPath` returns a string unchanged (853).
- **Reach.** A model host needs `write: true` plus `allowWrites: true` for `tosi_write`, and a declared scope for `tosi_read`. The behaviour is identical in the published 1.10.12 bundle, so shipping does not change exposure.
- **Why it is not fixed now.**
  - The fix is one canonical form at the surface boundary. That is the same funnel the STOP line concerns, and it depends on the one-normaliser work (#4043, #4261).
  - It needs your decision: refuse a non-canonical spelling (a behaviour change on a published surface, since `[=key]` is how a key containing a dot is addressed) or re-spell it.
  - Open GitHub #32 and #52 are the same cause.
  - If the STOP plan turns out tractable now, D1 should close in the same remediation, under the same re-review.
