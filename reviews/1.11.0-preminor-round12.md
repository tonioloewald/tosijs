## Blocker — fix before publish

### B-1 — eight published versions leak secrets through `describe()`/`tosi_describe`, npm `latest` is one of them, none deprecated, no advisory filed
`CHANGELOG.md:155` · lens: blast-radius · **verified** (registry re-checked in this triage)

Re-verified against the live registry, not taken from the CHANGELOG:

- `npm view tosijs dist-tags` → `{ beta: '1.7.0-beta.2', rc: '1.8.0-rc.3', latest: '1.10.1' }`.
- `npm view tosijs@<v> deprecated` for 1.8.0, 1.9.1, 1.10.0, 1.10.1 → **empty on every one.**
- No GitHub advisory exists in either the global NPM DB or the repo-level advisory list.

1.10.1 is inside the disclosed affected range (1.8.0 … 1.10.1), so **every `npm i tosijs` today installs a version whose `describe()` publishes, in cleartext and in the documented `manifest` production posture, exactly the values `read()` refuses** — via `tosi_describe`, the one WebMCP tool registered unconditionally in every posture. The verifier reproduced it against the actual npm tarball for 1.10.1: a `data-tosi-secret` region's magic-link token emitted in `href`, with `text` on the same record correctly withheld and **no** `secret: true` flag, so the suppression reads as plain absence. The disclosure itself instructs affected users to rotate credentials.

**This is entirely outside the repo.** Tagging and publishing 1.11.0 is definitionally inert for a pinned consumer, a lockfile, or `npm audit`. `npm deprecate` is the only channel that reaches a pinned consumer at install time; a published GitHub advisory is the only channel that reaches Dependabot. Neither has been used.

The CHANGELOG and `TODO.md:3-15` (both in this diff) now correctly state the question and record it as the maintainer's. **That is progress, and it is not the ask.** The finding is satisfied by *any* recorded answer plus the matching action — "below the bar at ~1,082 downloads/week, mostly automated" is a perfectly good answer, and the honest mitigation (the agent surface is opt-in and must be explicitly opened past the CLOSED default) supports it. What is not acceptable is a ninth round re-asking.

**Fix.** Decide, then execute, before `npm publish`:
- If **act**: publish 1.11.0 *first* (so there is a non-vulnerable version to point at), then `npm deprecate 'tosijs@>=1.8.0 <1.11.0' '<message pointing at 1.11.0 and the rotation advice>'`, and file a GitHub security advisory so scanners see it.
- Either way: replace the open question in `CHANGELOG.md` with the decision and delete `TODO.md:3-15`, so round 13 cannot re-ask it.

**Ordering hazard:** publishing 1.11.0 moves `latest` off 1.10.1, which removes the fresh-install exposure but **not** the pinned-consumer exposure. Do not treat the `latest` move as closing this.

**One precision, not material:** the leak needs `manifest` or `all`; the CLOSED default gates the DOM walk off entirely. "Read-only production posture" is fair; "default posture" is loose.

*Re-review scope: Tier 0 only — a registry action plus two prose edits.*

## Majors — fix in the same pass (both in round-11's own remediation)

### M-1 — `auditAccessibility()` fabricates `anonymous-affordance`/`target-size` on records whose text was withheld by **containment** — silently, with no flag and no abstention
`src/audit.ts:214` · lens: correctness · **verified by execution**

Round 10 split `harvestWouldLeak` into `'own' | 'contains'` and correctly stopped `suppressHarvest` setting `record.secret` on mere containment. But `suppressHarvest` still returns `true` for `'contains'`, so a containment-suppressed record ships with `text` stripped and **no `secret` flag**. Round 11's new gate reads `w.secret === true` — the **flag** — when the question it means to ask is the **decision** "was this record's content withheld". Confirmed in source: `harvestWouldLeak` (`src/agent.ts:1742`) returns `'own'` only for record-level secrecy; `suppressHarvest` sets the flag only on `'own'`; `audit.ts:214` keys on the flag.

Measured (happy-dom, mocked rects, HEAD sources, `expose: 'all'`):

- `a({href:'/reset'}, 'Forgot password?', input({type:'hidden', name:'csrf'}))` at 120×18 → record `{tag:'a', href:'/reset', bounds:{120×18}}`, no `text`, no `secret`. Audit reports `['anonymous-affordance' (error), 'target-size' (warn)]`, `failed = 1`, `skipped = []`.
- The **byte-identical link without the hidden input** → zero findings, `failed = 0`.
- Control for the fix that *did* land: the same link marked `data-tosi-secret` → `failed = 0` **with the skip note present**.

So the `secret` case abstains and says so; the containment case accuses silently. One bare CSRF input (`input[type=hidden]` is in `SECRET_INPUT_TYPES`) is enough. This is exactly the fabrication round 11 set out to kill — an `error` inflating `report.failed`, the number a CI gate asserts on, printing "add visible text" at an element that has visible text — arriving with no marker and nothing downstream able to tell it from a real finding.

**Two honest corrections to the report's write-up**, neither changing the verdict: its illustrating `div[role=button]` gets `target-size` either way (floorplan's WCAG 2.5.8 inline exemption is `tag === 'a'`-gated, `src/schematic.ts:393`), so only `anonymous-affordance` is fabricated there; `unnameable-action` is a genuine finding in that shape, not fabrication. The `<a>` shape — round 11's own worked example — fabricates both.

**Fix.** Do **not** re-flag containment as `secret` (round 10 removed that for a good reason — floorplan 0.5.0 renders `secret: true` as `[withheld]`). Publish the **decision** as its own non-redacting signal: have `suppressHarvest` set e.g. `record.contentWithheld = true` for **both** block kinds, and key audit.ts on that field rather than on `w.secret`. The published description currently carries no field distinguishing "text withheld by containment" from "no text" — agent.ts must publish the decision before audit.ts can ask it, so this is not a one-liner in audit.ts. Add the contained-CSRF pin beside the existing secret-link test; the two must audit the same way.

### M-2 — the same gate over-abstains: `target-size` is skipped on **every** `secret` record though `bounds` is never redacted, and the shipped remedy is false
`src/audit.ts:210,220,281` · lenses: blast-radius + correctness (merged; blast-radius severity kept) · **verified by execution**

`bounds` survives redaction, and `targetSizeFinding`'s only text-dependent exemption is `w.tag === 'a' && text !== '' && width > height`. So for every `input`/`button`/`div`, and for any `<a>` not wider than tall, the geometry verdict is fully determined by fields that survive — and the blanket `nameRedacted ? null : targetSizeFinding(...)` discards a true positive with no false-positive protection.

Measured:
- `a({href:'/x?token=T', 'aria-label':'Reset password'})` inside a `data-tosi-secret` region at 16×16 → record `{tag:'a', secret:true, label:'Reset password', interactive:true, bounds:{16×16}}` — **the accessible name is right there** and the geometry exact — yet the audit reports no `target-size`. The byte-identical link outside the region reports it.
- A secret `<button>` with `label:'Pay now'` at 16×16 → nothing.

**The shipped remedy is untrue, and it ships in the tarball.** The skip note, the block comment at `src/audit.ts:200-213` and `CHANGELOG.md:47` all promise "`aria-label` survives redaction and restores every one of these rules." Measured: it restores `anonymous-affordance` only **vacuously** (a named record cannot trip it anyway), does **not** restore `target-size`, and can **never** restore `label-hidden-by-placeholder`, because `src/agent.ts:1857` is `if (placeholder && !secretHere) record.placeholder = placeholder` — a secret record never carries one. An author who follows the printed instruction, re-runs, and sees nothing concludes a genuinely 16×16 control is fine. The note's premise "their name and text were withheld" is also false whenever the name came from `aria-label`. `CHANGELOG.md` is in `files`.

**One scope correction in the code's favour, and it is why this is major and not blocker.** The blanket skip *is* justified for the shape that motivated it — a wider-than-tall `<a>` whose visible text was redacted, where the exemption genuinely cannot be evaluated — and for `anonymous-affordance` generally, because `<label>` does **not** survive redaction (`associatedLabel` returns undefined when `referencedNodeIsSecret`, so `<label>Password <input type=password></label>` yields a record with no `label` at all). For that rule, keying on the flag *is* keying on the decision. The defect is that one shared `nameRedacted` was applied to three rules that read three different fields. `target-size` is a `warn`, so `report.failed` is unaffected — but the false negative sits on login/reset regions authors mark most carefully.

**Fix.** Gate each rule on the field it actually reads, not on one shared flag:
- `target-size` — suppress only for `w.secret === true && w.tag === 'a'` (the only text-keyed branch), or better, publish a content-free `hasText: true` hint on redacted records so the inline exemption can run without disclosure, and drop the skip entirely.
- `anonymous-affordance` — keep, narrowed to `w.secret === true && w.label == null`.
- `label-hidden-by-placeholder` — drop the arm (dead; see follow-ups).
- Rewrite the skip note and `CHANGELOG.md:47` to say what is true, and build the note from the rules actually suppressed rather than a fixed three-rule string.
- Add both missing pins: a secret control with **no** name must still report `anonymous-affordance`; a **named** secret control at 16×16 must report `target-size`.
