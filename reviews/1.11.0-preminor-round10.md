## Blockers (fix before tag)

### B-1 — withholding `href` deletes secret links from `describe()` entirely; the map is silently incomplete, not redacted, and the a11y audit goes quiet on them
`src/agent.ts:1832` and `src/agent.ts:2576` · correctness/security · **verified by execution at HEAD and against `v1.10.1`**

1.11.0's B1 fix makes `describeElement` skip `record.href` when `secretHere`. But the only route by which a bare link becomes *wired* reads the **published record**, not the element:

```js
if (!scoped && record.href != null && record.tag === 'a') { wired = true }
```

With `href` suppressed, `wired` stays false, `agent.ts:2661` does `seen.delete(el); return undefined`, and the link never enters the map. The structural tier only re-visits headings, landmarks and custom-element ancestors, so `<a>` is not recovered.

Measured, fixture `<div data-tosi-secret><a href="/reset?token=SEKRET"></a></div>` with `expose: 'all'`:

| | `describe().wiring` | `auditAccessibility` |
| --- | --- | --- |
| v1.10.1 | `[{tag:'a', href:'/reset?token=SEKRET', bounds:16×16}]` | `anonymous-affordance`, `target-size` |
| HEAD | `[]` | `[]` (skipped: "the map contains no wired elements") |

Three costs: an agent cannot see that a navigation affordance exists in a secret region *at all*; the a11y instrument stops reporting real defects in exactly the regions authors mark most carefully (login/reset flows); and floorplan 0.5.0's brand-new `[withheld]` / `redacted: true` rendering is unreachable for bare links because no record is ever produced. A secret link **with** an aria-label and visible text also vanishes, so the file's own "a name still survives secrecy — dropping it would trade a leak for a false `anonymous-affordance`" reasoning is defeated.

Four shipping documents state the opposite: `src/agent.ts:80-91`, the `AgentWiringRecord.href` docstring at `src/agent.ts:422-427`, `CHANGELOG.md`, and `Migration.md:44-48` ("Records for secret-marked elements no longer carry `href`…" — presupposes the record exists). Scoped postures are unaffected (bare links were never mapped under an allowlist), so this is an `expose: 'all'` regression — the posture in which the audit and the schematic are documented to be run.

No test catches it: every secret-anchor fixture in `src/agent.test.ts` (~3011, 3017, 3185) gives the anchor a `bindText`, wiring it by another route, and runs scoped.

**Fix:** ask the element, not the redacted record — `if (!scoped && record.tag === 'a' && el.getAttribute('href') != null) wired = true`. Add two pins that fail against HEAD: (1) a bare `<a href>` in a `data-tosi-secret` region appears in `wiring` with `secret: true`, no `href`, and the token substring absent from `JSON.stringify(describe())`; (2) `auditAccessibility()` still reports `anonymous-affordance` + `target-size` for a nameless 16×16 secret link.
**Re-review scope:** correctness + blast-radius over the remediation diff only — re-check the other `wired = true` sites for the same read-the-record-after-suppression pattern (`record.contentEditable` at 2581 is safe today; `record.component` at 2629 is not suppression-sensitive).

### B-3 — the `tosijs/agent` reference page tells consumers the release's headline new exports disagree with the audit, and points at a deleted private `auditView`
`src/index-agent.ts:21-29` · correctness + blast-radius (merged; blast-radius' blocker severity kept) · **verified by execution**

The published ⚠️ block still reads: *"These are the RENDERER's answers, and `auditAccessibility()` deliberately differs from them in three places — it ignores producer `flags`, exempts `0×0`, and treats a list-bound element carrying direct evidence as a control … the adjustment (`auditView`) is private because it is a workaround, not API."*

Commit `4c47cd5` adopted floorplan 0.5.0, folded all three carve-outs into the shared rule and **deleted `auditView`** (no definition or call survives; `src/audit.ts:191,253` calls `isInteractive`/`targetSizeFinding` raw). Executed at HEAD, exports and audit agree on all three named shapes:

| shape | audit `target-size`? | `targetSizeFinding` |
| --- | --- | --- |
| 10×10 button + `flags:[{kind:'target-size'}]` | yes | `"10×10 — below 24×24"` |
| 0×0 button | no | `null` |
| list-bound 20×20 `<select>` with `⟷` evidence | yes | `"20×20 — below 24×24"` |

**The callout is not merely stale, it is inverted**: `honorProducerFlags` defaults to `false` and only `schematic()` opts in (`src/schematic.ts:704`), so the exports give the *audit's* answer by default and the renderer is the one that adjusts. A consumer following "use these if you want the drawing's" gets the opposite.

Blast radius doubled this release: `docs/index-agent/index.html:97` renders it verbatim (committed and deployed), and `package.json` `files` now includes `/src`, so `src/index-agent.ts` ships in the tarball for the first time. Self-inflicted inside this cycle — added by `5742459` (true against floorplan 0.4.0), invalidated three commits later by `4c47cd5`, which updated `audit.ts` and `UPSTREAM.md` but not this file. The point of exporting `isInteractive`/`targetSizeFinding`/`TARGET_SIZE_DEFAULT` is to stop downstreams re-implementing them or installing a second floorplan; this page tells them to.

**Fix:** rewrite the block to state what is true (as of floorplan 0.5.0 the predicates **are** the audit's rule; the only knob is `targetSizeFinding`'s `honorProducerFlags`, default `false` = the lint's answer, `schematic()` passes `true`); rebuild so `docs/` and the ePub follow and `sourceFingerprint()` re-stamps.
**Re-review scope:** Tier 0 only.

### B-4 — the opt-in agent surface's cost is published as "~11 kB gz" in two shipping doc blocks; the real marginal cost is ~15.3 kB and the generated README token says 17.6 kB

Extending the generator is the class-closing fix but is not required for this tag.
**Severity note:** documentation-only, no runtime consequence — kept at blocker under this project's convention (blocker = fix-before-tag, impact rated separately) because the figure is the entire basis for the import decision the page asks the reader to make.

## Majors (decide before the tag; not blocking on their own)

### M-1 — `record.secret` is set on mere CONTAINMENT and now drives full redaction in the vendored renderer, while the same record still ships its content in cleartext
`src/agent.ts:1661-1665`, `1708-1728`, `2523` · security · **verified by execution**

`suppressHarvest()` is now called unconditionally (correct — it is how the `checked` guard gets reached), and `harvestWouldLeak()`'s third arm is `deepHas(el, SECRET_CONTROL_SELECTOR)` — pure subtree containment, with `input[type=hidden]` in the selector. floorplan 0.5.0 (new this release; `git show v1.10.1:src/schematic.ts` has **no** secret handling at all) treats `secret` as a full redaction order. The flag went from inert to visible.

Two costs, both reproduced:
1. **Availability.** `div({onClick, ariaLabel:'Sign in panel'}, span('Sign in'), input({type:'hidden',name:'csrf'}))` renders as `<div> [withheld]`, legend `redacted: true`, `svg.includes('Sign in panel') === false`. One bare CSRF input — the commonest shape on the web — blanks the caption of every wired ancestor.
2. **The payload contradicts itself.** `src/agent.ts:403-405` documents `secret` as "the producer WITHHELD facts"; `src/schematic.ts:624-625` says "`redacted` must never co-occur with the facts it claims were withheld". Here nothing was withheld — `{tag:'shadow-widget', text:'Dashboard ⟵ appT.ui.title', secret:true}` is the literal output for this release's own fixture at `src/agent.test.ts:2954`, and the new CONTROL test at `src/agent.test.ts:3575` produces `{tag:'div', value:'v ⟷ c41z.wrap', secret:true}`. That control passes only because it asserts on `agent.read()` and never on the record or the drawing.

This release deliberately narrowed *upward path* propagation so a bare hidden input does not poison ancestors (`propagates` gate, `agent.ts:1404-1410`, three CONTROL tests). The record-level containment arm was not narrowed with it.

**Fix:** split the two meanings. `suppressHarvest()` should keep meaning "do not harvest this element's free text" (containment is the right reason) but set `record.secret = true` only when the RECORD is genuinely secret — a secret control, inside a `data-tosi-secret` region, or bound to a secret path. At minimum apply the same `propagates`-style narrowing to the containment arm. Add the invariant as a test: **no record may carry both `secret: true` and a content field.**

### M-2 — the release publishes a repro-grade inventory of three live leaks and instructs users to rotate credentials, with no SECURITY.md, no private channel, and no recorded advisory decision
cross-cutting · blast-radius · **verified** · *sixth consecutive ask*

`src/agent.ts:105` and `CHANGELOG.md:194` enumerate three still-leaking shapes ("verified by execution"), and `CHANGELOG.md:79-89` names all eight affected versions (1.8.0 … 1.10.1) and says "treat those tokens as disclosed … Rotate them." Both ship in the tarball (`files` includes `/src` and `/CHANGELOG.md`) and both are published doc blocks on tosijs.net.

Verified against the working tree, the GitHub API and the registry: `SECURITY.md` has **never existed on any branch**; `.github/` has only `workflows/`; private vulnerability reporting is `{"enabled": false}`; `package.json` has no `bugs` field; `security-advisories` returns `[]`; all eight affected versions have `deprecated: None`; `dist-tags.latest` is still 1.10.1, itself affected. The only reporting route in existence is the public issue tracker.

Two propagation failures: a consumer pinned to 1.10.x gets **zero** signal (and `npm deprecate` — which *would* print at install time, the one channel that reaches them — was never considered), and a third party who reads the published inventory, builds a repro and finds a fourth shape has nowhere private to send it.

Population is ~1,030 downloads/week across the affected range (`api.npmjs.org/versions/tosijs/last-week`), plausibly mostly automated. **"Below the bar, because N/week" is a perfectly good answer** — an absent answer is not, which is why this is the sixth ask. Round 6 and round 7 both asked; the round-7 transfer to `TODO.md` demonstrably happened for six other items and dropped this one.

**Fix:** add a ~15-line `SECURITY.md` (supported versions + a private address), add it to `files` so it ships with the inventory, and record the advisory judgement in one sentence in `TODO.md` or the CHANGELOG.
