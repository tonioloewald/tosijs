## Fix before the tag

This finding is verified and rated minor (lens severity uncertain), but it sits in the remediation itself. SECURITY.md:54-59 says "a write replacing a granted action" is in scope with no caveat, so a reader would believe this case is covered.

- **Function `actions` grant: the SEC-9 check fails open above an action** (security; `src/declarative-binding.ts:289-292`). In function mode, `touchesAction` checks only the path and its ancestors, never its descendants. Repro: `{read:['app'], write:['app'], actions: p => p === 'app.checkout'}` plus `<input data-tosi-bind-value="app">`, then type a value, and `app` is replaced by a string. The doc block (lines 81-82) discloses this; SECURITY.md does not. Related edge: an id-path action grant (`app.list[id=3].pay`) does not overlap the markup path `app.list[0]`.
  - Preferred fix (fail closed): refuse a two-way binding whose target's current value is an object or function, both at hydration and in fromDOM. This also closes the id-path case. Minimum fix: add the function-grant caveat to SECURITY.md.
  - **Clears when:** a test with a function `actions` grant and `bind-value` on the ancestor `app` is refused, and the test goes red with the fix reverted. If only the doc route is taken, SECURITY.md and the doc block must say the same thing.
