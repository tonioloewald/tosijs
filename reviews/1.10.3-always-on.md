## Blockers (2) — both confirmed

### BLOCKER-1 — `src/docs/bind-vs-observe.md:115` states the exact inverse of the set trap *(correctness, confirmed)*

The new page's § "Two things worth knowing either way" reads:

> **An unchanged scalar notifies nobody.** Assigning a value that `!==` the current one does not call `touch()` at all…

`src/xin.ts:1116` and `:1436` are both `if (existing !== value && setByPath(…)) touch(path)`. **`!==` is the condition that *fires* `touch()`.** Verified empirically: same-value write → 0 notifications; different-value write → 1. The bolded heading is right and its body says the opposite, so a reader cannot tell which half to trust.

It is attached to the page's own recommended `bind(canvas, 'scene.time', { toDOM: (el, t) => renderFrame(el, t) })` and the paragraph builds on it ("an expensive custom redraw is skipped for free"). A reader concludes tosijs skips the redraw when the value *changed* — and either adds a change-guard that can never fire, or omits one they need and ships a per-frame redraw they believed was free.

Already propagated: present in `docs/bind-vs-observe/index.html`, `docs/docs.json`, `docs/tosijs.epub`, and — since `/src` is in `package.json` `files` — in the tarball.

**This is the same class the release exists to retract** (AAR 1.10.2: *"shipped a false remedy in a security note"*), in the release's other new doc.

- **Fix:** swap `!==` → `===`. One occurrence (`grep -rn 'that \`!==\` the' src/ README.md` returns only line 115). Regenerate docs + epub.
- **The page's footer claims "The behaviours described here are pinned by `tests/bind-lifecycle.pw.ts`" — this behaviour is pinned by nothing.** Add a fourth arm: assign the same scalar → `toDOM` run count unchanged; assign a deep-equal but distinct object → count increments. That also pins the "identity, not deep equality" half of the same paragraph.
- **Re-review scope:** Tier 0 only for the character swap + regeneration; correctness over the remediation diff if the test arm lands with it.

### BLOCKER-2 — `SECURITY.md:23` declares the version being released unsupported *(blast-radius / security policy, confirmed)*

```
| 1.11.x   | ✅            |
| ≤ 1.10.x | ❌ — upgrade  |
```

This release is **1.10.3**. `npm view tosijs versions` tops out at 1.10.2 and `latest` is 1.10.2 — **no 1.11.x exists**, so the instruction cannot be followed, and the currently-published `latest` already declares itself unsupported. `/SECURITY.md` is in `files` (confirmed present verbatim in the published `tosijs@1.10.2` tarball), and it is the repo-root policy backing GitHub's Security tab (no `.github/SECURITY.md` override).

A researcher who finds a real agent-surface leak on 1.10.3 — exactly the class this file's Scope section solicits, and the class **tosijs#41 is still open on** — reads that their line is unsupported and the remedy is to upgrade, and burns a round or does not report. It suppresses the highest-leverage inbound channel the project has.

Provenance is oversight, not intent: the renumber commit `ddcb9cd` edited this file (lines 46/50, `1.11.0` → `1.10.2`) and missed 23–24. That commit's message documents *two* deliberate exceptions; this is an undocumented third, so the release's own exception accounting is off by one. `git diff v1.10.2...HEAD -- SECURITY.md` is empty — 1.10.2 shipped it, 1.10.3 re-ships it.

- **Fix:** `| current minor | ✅ |` (renumber-proof, and matches the prose two lines above: *"Fixes land on the current minor"*). Confirmed this is the **only** surviving `1.11` reference in the shipped set.
- **Re-review scope:** Tier 0 only.
