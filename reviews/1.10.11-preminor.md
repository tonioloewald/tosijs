## Blockers (fix before the tag)

### B1. enableDeclarativeBinding executes a value granted only `read`, as JavaScript or CSS (security, confirmed)
- **Where:** `src/declarative-binding.ts:214` (`check()` for `text`, `value` and inert props).
- **What happens:** `<script data-tosi-text="app.comment"></script>` in server-rendered markup, with `enableDeclarativeBinding({ read: ['app'] })`, makes `bindings.text` set `textContent`. An empty parser-inserted script is not yet "already started", so it executes. Reproduced against the committed `dist/module.js` in real Chromium and Firefox: `window.PWNED === 1`. It also executes with `createContextualFragment` and with `elements.script()`. `<style data-tosi-text>` applied the attacker's CSS, which gets past a script-only CSP. `data-tosi-prop-text-content` reaches the same sink.
- **Why it blocks:** this breaks the feature's headline promises, "Nothing is evaluated" and "showing is not acting", on a new opt-in trust boundary.
- **Fix:** refuse every binding on `HTMLScriptElement`, `SVGScriptElement` and `HTMLStyleElement`, and consider `<template>`, `<iframe>` and `<object>` too, whatever the grants (the way `NEVER` handles `srcdoc`). Add these elements to the refusal-table test, and add a browser-lane case with a parser-inserted empty `<script>`.
- **Re-review scope:** security and correctness over the remediation diff, including a real-browser run.

### B2. The #56 fix is incomplete: `[__proto__]` still hands out `Object.prototype` (security, confirmed)
- **Where:** `src/xin.ts:1294`. The guard compares the raw `_prop`; the brackets are stripped and compound paths are split *after* the check.
- **What happens:** `xin['app.map[__proto__]'].x = 1`, `xin.app.map['[__proto__]'].x = 1` and the same two on `boxed` all succeed, and afterwards `({}).x === 1`. Four of nine spellings polluted the prototype. The dotted form and the bare key do throw.
- **Why it blocks:** the CHANGELOG presents 1.10.11 as the fix and plans an npm deprecation pointing users at it, but 1.10.11 is still exploitable through the computed-key shape #56 describes.
- **Fix:** apply the guard to the *normalised* key: after the bracket strip, and on every base and sub path the compound branch splits off. Route it through `by-path`'s `assertSafeKey` / `FORBIDDEN_SEGMENTS` so there is one list. Extend the #56 test to enumerate every spelling the trap normalises. Fold in the unverified correctness lead about the declarative PATH check accepting `__proto__`, `constructor` and `prototype`: reuse the same predicate there.
- **Re-review scope:** security over the get-trap remediation; correctness and blast-radius over the remediation diff.

## Fix before the tag (verified majors)

### M1. Declarative grants diverge from the agent manifest: SEC-9 is dropped, so a two-way binding can overwrite a granted action (blast-radius, confirmed)
- `src/declarative-binding.ts:250`. With `write: ['app']` and `actions: ['app.checkout']`, `<input data-tosi-bind-value="app.checkout">` replaced the function with the string `'pwned'`. `agent.ts`'s `hitsDeclaredAction` refuses this.
- **Fix:** move the read, write and act predicates, including `hitsDeclaredAction`, into one shared module that both surfaces call.
- **Clears when:** a test binding `bind-value` on an action path, and on an ancestor of one, fails with the fix reverted.

### M2. `actions` grants are prefix roots, so inherited methods can be called from markup (security, confirmed)
- `src/declarative-binding.ts:168`. With `actions: ['ps']`, `<button data-tosi-on-click="ps.items.splice">` emptied the array. The agent's `call` requires an *exact* action path. The same prefix rule also makes any extension of an action path "trusted to act" for `href`/`src`.
- **Fix:** match actions exactly, as the manifest does, or at minimum require the target to be an own data property and never an inherited one.
- **Clears when:** refusal tests for `splice`, `push` and `toString` fail with the fix reverted.

### M3. "One manifest can drive both" is false (docs, confirmed; duplicate of the blast-radius minor)
- `src/declarative-binding.ts:73-83` and `CHANGELOG.md:39-40`. Passing an `AgentExpose` such as `{ roots, actions, write: true }` throws `TypeError: (grant ?? []).map is not a function`. Without `write`, `roots` is ignored and every element warns "not granted to read", without naming the misnamed key. The claim also ships in `llms.txt`.
- **Fix:** either accept the agent's shape (`roots` → read, boolean `write`) through the shared grant module from M1, or remove the claim. In both cases, validate options at the boundary: an unknown key or a non-array, non-function grant should give a message naming the expected option.
- **Clears when:** a test passes a real `AgentExpose`, or a test asserts the named error.

M1–M3 need no separate re-review, but they land in the same diff as B1, so the B1 re-review covers them.
